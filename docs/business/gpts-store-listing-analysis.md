# 智簽公文系統上架 GPTs Store 可行性分析

**報告日期**: 2025年12月13日  
**專案**: AI 採購簽呈生成系統（智簽公文）  
**評估目標**: 分析智簽公文是否適合在 OpenAI GPTs Store 上架

---

## 📋 執行摘要

本報告針對「智簽公文系統是否適合在 GPTs Store 上架」進行深入分析。經過技術、市場、政策等多維度評估，我們的結論是：

### 核心結論

**智簽公文系統 ⚠️ 不太適合直接上架 GPTs Store**

主要原因：

1. **技術限制嚴重**：GPTs 無法實現智簽公文的核心功能（Word 文件下載、草稿管理、本地儲存）
2. **用戶體驗落差**：GPTs 的對話式介面無法提供現有系統的專業表單體驗
3. **目標用戶不匹配**：台灣政府採購人員不一定是 ChatGPT Plus 訂閱用戶
4. **商業模式衝突**：無法實現獨立的商業模式和收益控制

### 建議策略

我們建議採用 **「雙軌並行」** 策略：

| 策略 | 說明 | 優先級 |
|:---|:---|:---:|
| **主軌：獨立平台** | 繼續發展獨立的智簽公文平台（如前一份報告建議） | ⭐⭐⭐⭐⭐ |
| **輔軌：GPTs 版本** | 創建簡化版 GPT 作為引流和品牌曝光工具 | ⭐⭐⭐ |

## 第一部分：GPTs Store 上架要求分析

### 1.1 發布資格要求

#### 訂閱門檻

要在 GPTs Store 發布 GPT，創建者必須滿足以下條件之一：

**個人創建者**
- 必須是 **ChatGPT Plus**（$20/月）或 **ChatGPT Pro**（$200/月）訂閱用戶
- 免費用戶可以使用 GPTs，但無法創建或發布

**企業創建者**
- 屬於啟用 GPT 創建功能的 **Enterprise 工作區**
- 企業管理員可通過工作區設定控制創建權限

**對智簽公文的影響**：
- ✅ 訂閱門檻不高（$20/月），可接受
- ⚠️ 需要持續訂閱才能維護 GPT

#### 身份驗證要求

發布到公開 GPT Store 前，必須驗證 **Builder Profile**（建構者檔案）。有兩種驗證方式：

**選項 1：姓名驗證**
- Builder 名稱將與 ChatGPT Plus 帳單檔案上的姓名匹配
- 適合個人創建者

**選項 2：網域驗證**
- 需要擁有網域（例如：`procurement-ai.com`）
- 需要添加 DNS TXT 記錄進行驗證
- 可顯示「by procurement-ai.com」而非個人姓名
- 每個 Builder Profile 只能附加一個已驗證的網域

**對智簽公文的影響**：
- ✅ 建議使用網域驗證，更專業
- ✅ 可購買專屬網域（成本低）
- ⚠️ 需要技術能力設定 DNS 記錄

### 1.2 技術能力與限制

#### GPT 的核心能力

GPTs 基於 ChatGPT，具有以下能力：

**對話式互動**
- 自然語言理解和生成
- 多輪對話記憶
- 角色扮演和個性化

**知識庫整合**
- 可上傳文件作為知識庫（Knowledge files）
- 支援 PDF、TXT、Markdown 等格式
- GPT 可從知識庫中檢索資訊

**工具使用**
- **網頁瀏覽**：可搜尋和訪問網頁
- **檔案上傳**：用戶可上傳檔案供 GPT 分析
- **程式碼執行**：可執行 Python 程式碼（Code Interpreter）
- **DALL·E 圖像生成**：可生成圖像

**Custom Actions（自定義操作）**
- 可調用外部 API
- 需要提供 OpenAPI 規範
- API 必須是公開可訪問的
- 需要處理認證和授權

#### GPT 的技術限制

**無法實現的功能**：

1. **無法直接生成 Word 文件下載**
   - GPTs 無法直接生成 `.docx` 格式文件供用戶下載
   - 可以生成 Markdown 或純文字，但需要用戶手動複製
   - 如果要生成 Word 文件，需要調用外部 API（Custom Actions）

2. **無法使用瀏覽器 localStorage**
   - GPTs 運行在 ChatGPT 環境中，無法訪問用戶瀏覽器的 localStorage
   - 無法實現本地草稿儲存功能
   - 所有狀態只能在對話中維持

3. **無法提供複雜的表單介面**
   - GPTs 是對話式介面，無法提供傳統的表單 UI
   - 用戶需要通過對話方式輸入資訊，體驗不如專業表單

4. **無法實現複雜的前端邏輯**
   - GPTs 無法執行 JavaScript 程式碼
   - 無法實現動態表單驗證、即時預覽等功能

5. **對話狀態有限**
   - 對話歷史有長度限制
   - 長時間使用可能丟失早期對話內容
   - 無法像 Web 應用那樣持久化用戶資料

**可以實現的功能**：

1. **採購簽呈內容生成**
   - ✅ 可以基於用戶輸入生成簽呈內容
   - ✅ 可以使用知識庫提供範例和法規參考
   - ✅ 可以進行多輪對話優化內容

2. **格式化輸出**
   - ✅ 可以輸出 Markdown 格式的簽呈
   - ✅ 用戶可以複製貼上到 Word
   - ⚠️ 但無法直接下載 Word 文件

3. **知識庫查詢**
   - ✅ 可以上傳政府採購法規、範例簽呈等作為知識庫
   - ✅ GPT 可以從知識庫中檢索相關資訊
   - ✅ 提供法規引用和範例參考

4. **Custom Actions 擴展**
   - ✅ 可以調用外部 API 生成 Word 文件
   - ⚠️ 需要建立和維護外部 API
   - ⚠️ 增加技術複雜度和成本

### 1.3 政策與合規要求

#### 必須遵守的政策

**OpenAI 使用政策**
- 不得生成有害、非法或誤導性內容
- 不得用於欺詐或詐騙
- 不得侵犯他人隱私或權利

**GPT 品牌指南**
- 不得冒充 OpenAI 或 ChatGPT
- 不得使用誤導性名稱或描述
- 需要清楚說明 GPT 的功能和限制

**隱私與安全指南**
- 如果使用 Custom Actions，需要提供隱私政策 URL
- 需要保護用戶資料安全
- 不得收集不必要的個人資訊

#### 禁止內容

**嚴格限制**：
- 冒充真實個人或實體
- 未經授權使用受版權保護的名稱、標誌或肖像
- 設計用於生成不允許內容的 GPTs

**對智簽公文的影響**：
- ✅ 智簽公文的功能符合政策要求
- ✅ 不涉及禁止內容
- ⚠️ 需要確保不使用受版權保護的政府標誌

#### 審核機制

**審核流程**：
- 每個 GPT 在出現在 Store 之前都會經過審核
- 自動化政策檢查
- 如果被標記，可能進行人工審核

**審核時間**：
- 大多數 GPTs 在幾分鐘內出現在 Store 中
- 某些可能需要更長時間，取決於內容和審核負載

**對智簽公文的影響**：
- ✅ 審核流程相對快速
- ✅ 智簽公文內容應該容易通過審核

## 第二部分：智簽公文上架 GPTs Store 的優劣勢分析

### 2.1 優勢分析

#### ✅ 優勢 1：龐大的用戶基礎

**ChatGPT 的用戶規模**

ChatGPT 擁有數億活躍用戶，GPT Store 為創建者提供了巨大的潛在用戶基礎。

**對智簽公文的價值**：
- 可以接觸到大量潛在用戶
- 無需自行建立流量來源
- 利用 OpenAI 的品牌和信任

**實際效益評估**：
- ⚠️ ChatGPT 用戶主要是國際用戶，台灣用戶比例較小
- ⚠️ 政府採購人員不一定是 ChatGPT Plus 訂閱用戶
- ⚠️ 需要 Plus 訂閱（$20/月）才能使用 GPTs

#### ✅ 優勢 2：零開發成本

**創建 GPT 無需編程**

創建 GPT 不需要編寫程式碼，只需要通過自然語言對話即可配置。

**對智簽公文的價值**：
- 可以快速創建原型
- 無需前端或後端開發
- 無需伺服器和資料庫

**實際效益評估**：
- ✅ 可以快速驗證概念
- ⚠️ 但功能受限，無法實現完整功能
- ⚠️ 需要持續訂閱 ChatGPT Plus（$20/月）

#### ✅ 優勢 3：品牌曝光機會

**GPT Store 的推薦機制**

GPT Store 有分類、排行榜、精選推薦等機制，優質 GPT 可以獲得平台推薦。

**對智簽公文的價值**：
- 可以獲得品牌曝光
- 如果進入精選或排行榜，可以獲得大量流量
- 建立「採購簽呈專家」的品牌形象

**實際效益評估**：
- ⚠️ GPT Store 已有 300 萬+ GPTs，競爭激烈
- ⚠️ 台灣政府採購是小眾領域，不易獲得推薦
- ⚠️ 國際用戶對台灣採購簽呈沒有需求

#### ✅ 優勢 4：快速迭代

**GPT 可以隨時編輯**

創建者可以隨時編輯 GPT 的配置、指令、知識庫等，無需重新發布。

**對智簽公文的價值**：
- 可以根據用戶反饋快速優化
- 可以隨時更新法規和範例
- 無需版本管理和部署流程

**實際效益評估**：
- ✅ 確實方便快速迭代
- ✅ 適合早期測試和驗證

### 2.2 劣勢分析

#### ❌ 劣勢 1：技術限制嚴重

**無法實現核心功能**

智簽公文系統的核心功能在 GPTs 中無法實現或體驗不佳：

| 功能 | 現有系統 | GPTs 版本 | 差距 |
|:---|:---|:---|:---|
| **Word 文件下載** | ✅ 直接下載 .docx | ❌ 無法直接下載 | **嚴重** |
| **草稿管理** | ✅ 本地儲存，隨時載入 | ❌ 無法持久化 | **嚴重** |
| **表單介面** | ✅ 專業表單 UI | ❌ 對話式輸入 | **中等** |
| **歷史記錄** | ✅ 完整歷史，可搜尋 | ⚠️ 對話歷史有限 | **中等** |
| **即時預覽** | ✅ Markdown 渲染 | ⚠️ 只能輸出文字 | **輕微** |

**結論**：GPTs 無法提供與現有系統相當的功能和體驗。

#### ❌ 劣勢 2：用戶體驗落差

**對話式 vs. 表單式**

智簽公文現有系統使用專業的表單介面，用戶可以清楚看到所有欄位和選項。GPTs 的對話式介面需要用戶逐步回答問題，體驗不如表單。

**用戶體驗對比**：

**現有系統（表單式）**：
```
採購品項：[_________________]
預算金額：[_________________]
採購理由：[_________________]
           [_________________]
預期效益：[_________________]
[生成簽呈] [儲存草稿]
```

**GPTs 版本（對話式）**：
```
GPT: 您好！我是採購簽呈助手。請問您要採購什麼品項？
用戶: 桌上型電腦 20 台
GPT: 好的，預算金額是多少？
用戶: 80 萬元
GPT: 請說明採購理由...
```

**問題**：
- 用戶需要多輪對話才能完成輸入
- 無法一次看到所有欄位
- 容易遺漏重要資訊
- 對於熟悉表單的用戶，體驗不佳

#### ❌ 劣勢 3：目標用戶不匹配

**ChatGPT Plus 訂閱門檻**

要使用 GPTs，用戶必須是 ChatGPT Plus 訂閱用戶（$20/月）。

**台灣政府採購人員的現況**：
- 大部分可能沒有 ChatGPT Plus 訂閱
- 政府機關可能不允許使用外部 AI 服務
- 資安考量可能限制使用
- 預算限制可能不願意個人付費訂閱

**市場規模影響**：
- 假設台灣有 20 萬潛在用戶
- 假設其中 5% 是 ChatGPT Plus 用戶 = 10,000 人
- 實際可觸及用戶大幅縮小

#### ❌ 劣勢 4：商業模式受限

**無法獨立定價**

GPTs 目前的收益模式：
- 創建者無法直接向用戶收費
- 收益來自 OpenAI 的使用量分成
- 分成比例和標準不透明
- 目前僅限美國建構者

**對智簽公文的影響**：
- ❌ 無法實現獨立的商業模式
- ❌ 無法提供付費版和免費版
- ❌ 收益完全依賴 OpenAI 政策
- ❌ 台灣創建者目前無法獲得收益

#### ❌ 劣勢 5：資料隱私疑慮

**資料儲存在 OpenAI**

用戶在 GPTs 中輸入的所有資訊都會儲存在 OpenAI 的伺服器上。

**對政府採購的影響**：
- ⚠️ 政府採購資訊可能涉及機密
- ⚠️ 政府機關可能不允許上傳到外部平台
- ⚠️ 資料主權和合規性問題
- ⚠️ 無法提供私有部署選項

**OpenAI 的資料政策**：
- ChatGPT Plus 用戶的對話不會用於訓練模型（預設）
- 但資料仍儲存在 OpenAI 伺服器
- 無法完全控制資料

#### ❌ 劣勢 6：平台依賴風險

**完全依賴 OpenAI 平台**

如果在 GPTs Store 上架，智簽公文將完全依賴 OpenAI 平台：

**風險**：
- OpenAI 可能隨時改變政策
- GPT 可能因違反政策被下架
- OpenAI 可能調整收益分成比例
- OpenAI 可能關閉 GPT Store（雖然不太可能）

**對比獨立平台**：
- 獨立平台完全自主控制
- 可以建立直接的用戶關係
- 可以自由調整商業模式
- 可以保護用戶資料隱私

## 第三部分：可能的挑戰與解決方案

### 3.1 技術挑戰

#### 挑戰 1：Word 文件下載

**問題**：GPTs 無法直接生成 Word 文件供用戶下載

**可能的解決方案**：

**方案 A：使用 Custom Actions 調用外部 API**

建立一個外部 API 服務，GPT 調用該 API 生成 Word 文件：

```
用戶 → GPT → Custom Action → 外部 API → 生成 Word 文件 → 返回下載連結
```

**優點**：
- 可以實現 Word 文件生成
- 用戶可以下載文件

**缺點**：
- 需要建立和維護外部 API
- 增加技術複雜度和成本
- 需要處理認證和授權
- 需要提供隱私政策 URL

**方案 B：提供 Markdown 格式，用戶手動轉換**

GPT 輸出 Markdown 格式的簽呈，用戶複製貼上到 Word 或使用轉換工具。

**優點**：
- 無需額外開發
- 簡單直接

**缺點**：
- 用戶體驗不佳
- 需要額外步驟
- 格式可能不完美

**方案 C：提供純文字，用戶手動複製**

GPT 輸出純文字格式的簽呈，用戶複製貼上到 Word 自行排版。

**優點**：
- 最簡單的方案

**缺點**：
- 用戶體驗最差
- 失去格式化優勢
- 與現有系統差距太大

**建議**：如果要上架 GPTs Store，建議採用**方案 A**（Custom Actions），但需要評估開發和維護成本。

#### 挑戰 2：草稿管理

**問題**：GPTs 無法使用 localStorage，無法實現本地草稿儲存

**可能的解決方案**：

**方案 A：利用對話歷史**

用戶可以在對話歷史中找到之前生成的簽呈。

**優點**：
- 無需額外開發
- ChatGPT 自動保存對話歷史

**缺點**：
- 對話歷史有長度限制
- 難以管理和搜尋
- 無法像現有系統那樣有結構化的草稿列表

**方案 B：使用 Custom Actions 儲存到雲端**

建立外部 API，將草稿儲存到雲端資料庫。

**優點**：
- 可以實現草稿管理
- 可以跨裝置同步

**缺點**：
- 需要建立和維護外部 API
- 需要用戶認證和授權
- 增加技術複雜度
- 資料隱私問題

**方案 C：放棄草稿管理功能**

GPTs 版本不提供草稿管理，僅提供即時生成。

**優點**：
- 簡化功能
- 降低技術複雜度

**缺點**：
- 失去重要功能
- 用戶體驗大幅下降

**建議**：如果要上架 GPTs Store，可能需要**放棄草稿管理功能**（方案 C），或者提供簡化版（方案 A）。

#### 挑戰 3：表單介面

**問題**：GPTs 是對話式介面，無法提供專業表單 UI

**可能的解決方案**：

**方案 A：優化對話流程**

設計清晰的對話流程，引導用戶逐步輸入資訊：

```
GPT: 歡迎使用採購簽呈助手！我會引導您完成簽呈撰寫。

GPT: 步驟 1/5：請輸入採購品項（例如：桌上型電腦 20 台）
用戶: 桌上型電腦 20 台

GPT: 步驟 2/5：請輸入預算金額（新台幣）
用戶: 800,000

GPT: 步驟 3/5：請說明採購理由...
```

**優點**：
- 清晰的步驟引導
- 降低用戶困惑

**缺點**：
- 仍然不如表單直觀
- 無法一次看到所有欄位
- 修改已輸入的資訊較麻煩

**方案 B：提供範本選擇**

讓用戶先選擇採購類型，GPT 根據範本提問：

```
GPT: 請選擇採購類型：
1. 財物採購（辦公設備、耗材等）
2. 勞務採購（顧問、維護等）
3. 工程採購（營建、修繕等）

用戶: 1

GPT: 您選擇了「財物採購」。請輸入採購品項...
```

**優點**：
- 針對性提問
- 減少不必要的問題

**缺點**：
- 仍然是對話式，不如表單

**建議**：採用**方案 A + 方案 B** 的組合，優化對話體驗，但需要接受無法達到表單 UI 的體驗水準。

### 3.2 市場挑戰

#### 挑戰 4：目標用戶觸及

**問題**：台灣政府採購人員不一定是 ChatGPT Plus 訂閱用戶

**可能的解決方案**：

**方案 A：提供免費試用引導**

在 GPT 描述中說明如何免費試用（如果 OpenAI 提供試用期）：

```
描述：
「智簽公文」是專為台灣政府採購人員設計的 AI 簽呈助手。
如果您還不是 ChatGPT Plus 用戶，可以免費試用 7 天。
```

**優點**：
- 降低用戶嘗試門檻

**缺點**：
- OpenAI 不一定提供免費試用
- 試用期後仍需付費

**方案 B：作為引流工具**

將 GPTs 版本定位為「簡化版」或「試用版」，引導用戶使用完整的獨立平台：

```
GPT 輸出：
```

**優點**：
- 利用 GPTs 獲得曝光
- 引導用戶到獨立平台
- 在獨立平台實現完整功能和商業模式

**缺點**：
- GPTs 版本功能受限
- 可能被視為「廣告」

**方案 C：針對已有 Plus 訂閱的用戶**

接受 GPTs 版本只能觸及小部分用戶，專注服務已有 ChatGPT Plus 訂閱的採購人員。

**優點**：
- 簡化策略
- 專注服務願意付費的用戶

**缺點**：
- 市場規模大幅縮小
- 錯失大部分潛在用戶

**建議**：採用**方案 B**（引流工具），將 GPTs 版本作為品牌曝光和引流渠道，主要業務在獨立平台。

#### 挑戰 5：資料隱私疑慮

**問題**：政府機關可能不允許將採購資訊上傳到 OpenAI

**可能的解決方案**：

**方案 A：在描述中說明資料政策**

在 GPT 描述中清楚說明資料如何處理：

```
隱私說明：
- 您的對話資料儲存在 OpenAI 伺服器
- ChatGPT Plus 用戶的對話不會用於訓練模型（預設）
- 如涉及機密資訊，建議使用我們的私有部署版本
```

**優點**：
- 透明化資料政策
- 讓用戶自行判斷

**缺點**：
- 無法解決根本問題
- 政府機關可能仍不接受

**方案 B：提供去識別化建議**

建議用戶在輸入時去識別化敏感資訊：

```
GPT: 請輸入採購品項（如涉及機密，可使用代號）
用戶: XX 型號設備 20 台（而非具體型號）
```

**優點**：
- 降低資料洩露風險

**缺點**：
- 影響簽呈的完整性
- 用戶仍需手動修改

**方案 C：明確定位為「非機密採購」**

將 GPTs 版本定位為僅供「非機密採購」使用：

```
適用範圍：
本工具適用於一般辦公用品、設備等非機密採購。
如涉及機密或敏感採購，請使用我們的私有部署版本。
```

**優點**：
- 明確使用範圍
- 降低合規風險

**缺點**：
- 限制使用場景
- 市場規模進一步縮小

**建議**：採用**方案 A + 方案 C**，明確說明資料政策和適用範圍，並引導需要高隱私保護的用戶使用獨立平台的私有部署版本。

### 3.3 商業挑戰

#### 挑戰 6：無法實現獨立商業模式

**問題**：GPTs 無法獨立定價，收益依賴 OpenAI 分成

**可能的解決方案**：

**方案 A：接受 OpenAI 的收益分成模式**

等待 OpenAI 開放收益計劃，並接受其分成比例。

**優點**：
- 無需自行處理支付
- 利用 OpenAI 的平台

**缺點**：
- 收益不透明
- 目前僅限美國建構者
- 台灣創建者何時能獲得收益不確定
- 分成比例可能不理想

**方案 B：將 GPTs 作為免費引流工具**

GPTs 版本完全免費，作為品牌曝光和引流工具，主要收入來自獨立平台。

**優點**：
- 利用 GPTs 獲得免費曝光
- 引導用戶到獨立平台付費
- 在獨立平台實現完整商業模式

**缺點**：
- GPTs 版本無法直接獲利
- 需要維護兩個版本

**方案 C：使用 Custom Actions 實現付費功能**

通過 Custom Actions 調用外部 API，在外部 API 中實現付費邏輯。

**優點**：
- 可以實現獨立的付費模式

**缺點**：
- 技術複雜度高
- 用戶體驗可能不佳（需要在外部網站付費）
- 可能違反 GPTs 政策

**建議**：採用**方案 B**，將 GPTs 版本定位為免費的引流工具，主要商業模式在獨立平台實現。

**獨立平台**：
1. 正式上線
2. 獲得前 1,000 位付費用戶
3. 建立模板市場
4. 招募創作者

**GPTs 版本**：
1. 收集用戶反饋
2. 持續優化 GPT
3. 分析引流效果
4. 調整推廣策略

#### 長期行動（12-24 個月）

**獨立平台**：
1. 擴大用戶規模至 10,000+
2. 年收入達 NT$ 50-100M
3. 成為產業標準
4. 探索國際化

**GPTs 版本**：
1. 評估效果
2. 決定是否繼續維護
3. 如果效果好，可以擴展功能（Custom Actions）

### 5.4 決策建議

#### 如果資源充足

**建議**：採用雙軌並行策略

- 主要投入獨立平台（80%）
- 同時創建 GPTs 版本作為輔助（20%）
- 利用 GPTs 獲得額外曝光和引流

#### 如果資源有限

**建議**：專注獨立平台，暫緩 GPTs 版本

- 100% 投入獨立平台
- 等獨立平台穩定後，再考慮 GPTs 版本
- 避免分散資源

#### 如果只是想快速驗證概念

**建議**：先創建 GPTs 版本

- 快速創建 GPT（1-2 週）
- 測試市場反應
- 收集用戶反饋
- 再決定是否投入獨立平台

### 5.5 最終建議

**智簽公文應該上架 GPTs Store 嗎？**

**答案**：可以，但僅作為輔助策略，不應作為主要策略。

**理由**：

1. **GPTs 版本的價值**：
   - ✅ 品牌曝光和引流
   - ✅ 低成本快速驗證
   - ✅ 利用 ChatGPT 用戶基礎

2. **GPTs 版本的限制**：
   - ❌ 無法實現核心功能
   - ❌ 用戶體驗不如獨立平台
   - ❌ 無法實現完整商業模式
   - ❌ 資料隱私疑慮

3. **最佳策略**：
   - 🎯 主要投入獨立平台（80%）
   - 🔄 輔助創建 GPTs 版本（20%）
   - 🔗 GPTs 引流到獨立平台

**總結**：GPTs Store 可以作為智簽公文的「試用版」和「引流渠道」，但獨立平台才是實現完整功能、最佳體驗和商業成功的關鍵。

## 報告結語

智簽公文系統是一個專業的政府採購簽呈生成工具，需要提供完整的功能、最佳的用戶體驗和嚴格的資料隱私保護。GPTs Store 雖然提供了龐大的用戶基礎和低成本的曝光機會，但其技術限制、用戶體驗落差和商業模式受限，使其**不適合作為智簽公文的主要策略**。

我們強烈建議採用「雙軌並行」策略：**主要投入獨立平台（80%），輔助創建 GPTs 版本（20%）**。獨立平台可以實現完整功能和最佳體驗，建立獨立的商業模式和品牌；GPTs 版本則作為品牌曝光和引流工具，將潛在用戶引導到獨立平台。

這種策略既能利用 GPTs Store 的優勢（低成本、大曝光），又能避免其劣勢（功能受限、體驗不佳），最終實現智簽公文的商業成功和產業領導地位。
